# 1.1 研究笔记

来自 dogfooding(`examples/url_shorten.rs`,URL 短链服务)与冻结期观察。
1.0 冻结期间不动手,只收集;1.0.0 发布后按需排期。

## API 摩擦点(dogfood 实测)

1. **闭包 handler 的 `Ok` 类型标注**(最高频摩擦,dogfood 中踩了 3 次):
   `post(|ctx| async move { ... Ok(Resp::ok(x)) })` 因
   `Result<T, E: Into<Error>>` 的 E 自由推断而编译失败,必须写
   `Ok::<_, Error>(...)`。命名 async fn + `-> Result<Resp<T>>` 别名返回
   则无此问题(默认类型参数在签名位参与展开)。
   候选方案(1.1 评估,均含取舍):
   - a) 框架提供 `desire::ok(data)` / `desire::err(..)` 构造函数,返回
     具体类型 `Concluded`——绕开 Result 推断,但与 `?` 的互操作变复杂
   - b) handler 只允许 `Resp<T>`/具体类型,错误统一走 `?` + From——
     语义收窄,破坏性
   - c) 文档继续兜底(现状),把 `Ok::<_, Error>` 写进 cookbook 显眼位置
2. **`ctx.host()` / `ctx.full_url()` 便捷方法**:构造绝对短链时需要
   手写 `ctx.header("host").unwrap_or("localhost:3000")` + 拼接。1.1 可加
   `host()`(Host 头或 remote 回退)与 `request_url()`(scheme + host +
   path + query)。
3. **重定向计数这类"前置副作用"要手动 `get_mut` + 计数**:属应用层
   逻辑,框架不收 —— 仅记录,不动。
